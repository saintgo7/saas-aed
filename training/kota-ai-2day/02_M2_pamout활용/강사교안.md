- **(멘트)** "화면 중앙 아래에 긴 텍스트 입력창이 있습니다. 여기가 여러분이 AI에게 말을 거는 곳, 즉 프롬프트를 입력하는 곳입니다."

- **(전환)** "자, 화면도 보셨으니 바로 첫 질문 해봅시다."

## 파트 2 — 첫 질문 함께 해보기 (라이브 데모 1) (15~28분)

### Slide 2-1 — 라이브 데모: 첫 질문

- **(화면)** 강사 실제 chat.pamout.com 화면 공유
- **(멘트)** "제가 지금 입력하는 걸 그대로 따라 입력해보세요. 복사 안 하셔도 됩니다. 직접 타이핑하시는 게 더 기억에 남습니다."

> **[라이브 데모 1 — 강사 타이핑 스크립트]**
>
> **입력 프롬프트 (강사가 화면에 직접 타이핑):**
> ```
> 특장차 제작 회사에서 품질팀에 근무하고 있습니다.
> 오늘 오전 회의에서 소방차 납품 일정이 2주 지연된다는 보고가 있었는데,
> 팀장님께 보낼 간단한 보고 이메일 초안을 작성해주세요.
> ```
>
> **예상 답변 흐름 (강사가 읽으며 해설할 포인트):**
> - AI가 "제목", "수신", "본문", "서명" 구조로 이메일을 작성함
> - "보시다시피, 제가 상황 두 줄만 설명했는데도 형식 갖춘 이메일이 나왔습니다."
> - "이게 LLM의 핵심입니다. 여러분이 써야 할 내용을 '어떻게 써야 하는지'까지 알고 있습니다."
> - "다만 날짜, 담당자 이름 같은 구체적 사실은 제가 안 알려줬으니 [괄호]로 비워뒀죠? 이 부분은 여러분이 채워야 합니다. 이게 '검증'의 첫 번째 포인트입니다."

- **(발문)** "여러분도 입력창에 같은 내용 쳐보세요. 제 것이랑 완전히 똑같이 나오는 분, 손 들어보세요." → (예상: 아무도 손 안 듦) → "맞습니다. LLM은 같은 입력에도 매번 다른 표현으로 답합니다. 그게 정상이에요."
- **(전환)** "이제 왜 답변이 다른지, 그리고 더 좋은 답을 받으려면 어떻게 질문해야 하는지 배워봅시다."

### Slide 2-2 — "좋은 질문 vs 나쁜 질문" 비교

- **(화면)** 두 프롬프트 나란히 비교

| 나쁜 질문 | 좋은 질문 |
|---|---|
| `이메일 써줘` | `소방차 납품 2주 지연을 품질팀장에게 보고하는 300자 이내 이메일 초안, 정중한 톤으로` |
| `보고서 써줘` | `리콜 현황 주간보고서, 항목: 차종·건수·원인·조치현황·예정일, 표 형식으로` |

- **(멘트)** "왼쪽처럼 물으면 AI가 최대한 짐작해서 답하지만, 여러분이 원하는 결과와 멀리 갈 수 있습니다. 오른쪽처럼 맥락을 주면 훨씬 정확한 답이 나옵니다."
- **(전환)** "이 '좋은 질문'을 체계적으로 만드는 방법이 바로 다음에 배울 '프롬프트 5요소'입니다."

## 파트 3 — 프롬프트 5요소 구조화 (RCTFE) (28~50분)

### Slide 3-1 — 5요소 개요

- **(화면)** 표: 5요소 RCTFE

| 요소 | 영문 | 설명 | 예시 |
|---|---|---|---|
| **역할(Role)** | Role | AI가 맡을 전문가 페르소나 | "당신은 자동차 안전기준 전문가입니다." |
| **맥락(Context)** | Context | 상황·배경 정보 | "우리 회사는 특장차 제작사로, 소방차 30대 납품 계약을 앞두고 있습니다." |
| **작업(Task)** | Task | 구체적으로 해달라는 일 | "아래 체크리스트를 검토해서 누락 항목을 찾아주세요." |
| **형식(Format)** | Format | 출력 형태 | "표 형식으로, 항목 / 현황 / 비고 3열로 정리해주세요." |
| **예시(Example)** | Example | 원하는 결과의 샘플 | "예시: 항목: 제동장치 / 현황: 미완료 / 비고: 부품 입고 대기" |

- **(멘트)** "5가지를 외울 필요는 없습니다. 하지만 오늘 90분 동안 이 프레임을 10번 쓰다 보면 자연스럽게 체화됩니다."
- **(멘트)** "5개를 전부 써야 좋은 프롬프트가 되는 건 아닙니다. 최소 역할 + 작업 + 형식 3가지만 있어도 답변 품질이 크게 올라갑니다."

### Slide 3-2 — 역할(Role) 부여 실습

- **(화면)** 역할 부여 before/after 비교
- **(멘트)** "역할을 주면 AI가 해당 분야 전문가 언어로 답합니다. '당신은 ISO 9001 심사원입니다'라고 하면 품질관리 용어로, '당신은 기술문서 편집자입니다'라고 하면 문서 구조에 집중합니다."

> **[라이브 데모 — 역할 비교]**
>
> **역할 없는 버전:**
> ```
> FMEA가 뭔지 설명해줘.
> ```
>
> **역할 있는 버전:**
> ```
> 당신은 자동차 품질관리 전문가입니다.
> 특장차 생산라인의 신입 품질팀원에게 FMEA(고장 모드 및 영향 분석)가 무엇인지,
> 실무에서 왜 중요한지 쉬운 말로 5줄 이내로 설명해주세요.
> ```

- **(멘트)** "두 번째 프롬프트처럼 역할 + 대상(신입 팀원) + 제약(5줄 이내)을 주면 훨씬 실용적인 답이 나옵니다."

### Slide 3-3 — 맥락(Context) + 작업(Task) 결합

- **(화면)** 맥락 추가 예시
- **(멘트)** "자동차 업무는 맥락이 중요합니다. 같은 '보고서 써줘'도 소방차인지 냉동탑차인지, 내부 보고인지 인증기관 제출인지에 따라 내용이 완전히 달라집니다. 그 맥락을 AI에게 알려주세요."

> **[실습 예시 — 맥락 풍부한 프롬프트]**
> ```
> [맥락] 우리 회사는 탱크로리 제작 전문 업체로, 다음 주 한국교통안전공단에
> 제원표 적합성 서류를 제출해야 합니다.
>
> [작업] 제원표에 반드시 포함되어야 하는 항목 목록을 작성해주세요.
>
> [형식] 번호 붙인 목록으로, 각 항목 옆에 왜 필요한지 한 줄 설명 추가.
> ```

- **(전환)** "이제 형식과 예시까지 더해봅시다."

### Slide 3-4 — 형식(Format) + 예시(Example)

- **(화면)** 표 출력 요청 예시
- **(멘트)** "형식을 지정하면 그대로 나옵니다. 표 달라면 표, 번호 목록 달라면 번호 목록, PPT 슬라이드 개요 달라면 슬라이드 개요로 줍니다. 출력 형태를 미리 정해두면 바로 문서에 붙여넣을 수 있습니다."

> **[형식 지정 예시]**
> ```
> 아래 표를 참고해서, 소방차 연간 점검 계획을 작성해주세요.
>
> [형식] 마크다운 표. 열: 점검 월 / 점검 항목 / 담당부서 / 비고
> [예시 행]
> | 1월 | 소화장비 기능 검사 | 안전팀 | 법정 의무 |
> ```

- **(멘트)** "예시 행 하나만 줘도 AI가 나머지를 그 형식에 맞춰 채워줍니다."
- **(전환)** "5요소 배웠으니, 목적별로 어떤 패턴을 쓰는지 빠르게 훑어보겠습니다."

## 파트 4 — 목적별 프롬프트 패턴 (50~65분)

### Slide 4-1 — 5가지 핵심 패턴

- **(화면)** 패턴 목록

| # | 패턴명 | 언제 쓰나 | 핵심 키워드 |
|---|---|---|---|
| 1 | **요약 패턴** | 긴 문서·회의록·보고서 핵심 추출 | "아래 내용을 N줄로 요약해줘" |
| 2 | **초안 작성 패턴** | 이메일·공문·보고서 초안 빠르게 생성 | "~을 위한 초안을 작성해줘, 톤: 정중/간결" |
| 3 | **표 만들기 패턴** | 데이터 정리, 비교 분석 | "표 형식으로 정리해줘, 열: A/B/C" |
| 4 | **아이디어 패턴** | 브레인스토밍, 개선안 도출 | "~에 관한 아이디어 10가지 제안해줘" |

## 파트 5 — 반복 수정(Refine) + 할루시네이션 검증 (65~80분)

### Slide 5-1 — Refine 3단계 전략

- **(화면)** Refine 단계 다이어그램

```
1단계: 처음 프롬프트 → 답변 받기
       ↓
2단계: 답변에서 부족한 부분 파악 → 추가 지시
       ("더 짧게", "표로 바꿔줘", "소방차 예시로 다시 써줘")
       ↓
3단계: 만족스러울 때까지 반복 (보통 2~4회면 충분)
```

- **(멘트)** "처음 프롬프트 하나로 완벽한 답변이 나올 거라는 기대는 접으세요. AI와의 대화는 편집자와 작가의 협업입니다. 초안 → 수정 → 최종본 과정을 AI와 함께 하는 겁니다."
- **(멘트)** "수정 지시는 짧아도 됩니다. '더 공식적인 문체로', '숫자 데이터 추가해줘', '배경 설명 부분 빼줘' 이 정도면 충분합니다."

### Slide 5-2 — 라이브 데모 2: Refine 시연

> **[라이브 데모 2 — 반복 수정]**
>
> **1회차 입력:**
> ```
> 특장차 품질관리 절차서 목차를 작성해줘.
> ```
>
> **1회차 답변 예상 흐름:**
> → AI가 5~8개 챕터 목차를 생성
>
> **2회차 수정 지시 (강사 타이핑):**
> ```
> 좋아요. 그런데 우리 회사는 소방차와 살수차만 만듭니다.
> 차종별로 다른 점을 반영해서 목차에 소방차/살수차 구분 항목을 추가하고,
> 각 항목 옆에 참조할 관련 법령명도 한 줄씩 추가해주세요.
> ```
>
> **2회차 답변 예상 흐름:**
> → 더 구체화된 목차, 소방차·살수차 분기, 자동차관리법·소방법 등 명시
>
> **3회차 수정 지시 (필요 시):**
> ```
> 법령 참조 부분에서 '자동차관리법' 조항 번호까지 넣어주면 더 좋겠는데,
> 정확하지 않으면 "(확인 필요)"로 표시해줘.
> ```

- **(멘트)** "3회차에서 중요한 지시를 했습니다. '정확하지 않으면 확인 필요로 표시해줘'. AI가 모르는 걸 지어내지 말고 표시하도록 유도하는 겁니다. 이게 할루시네이션 관리의 첫 번째 방법입니다."

### Slide 5-3 — 할루시네이션: 이해·판별·대응

- **(화면)** 할루시네이션 3단계 대응 표

| 단계 | 방법 | 예시 |
|---|---|---|
| **예방** | 프롬프트에 "모르면 모른다고 해줘" 포함 | `"확실하지 않은 정보는 (미확인)으로 표시해줘"` |
| **판별** | 숫자·날짜·법령·이름 → 반드시 원본 검증 | AI 답변의 조항 번호를 국가법령정보센터에서 확인 |
| **대응** | "이 부분 출처 알려줘" 또는 새 대화로 재확인 | `"방금 답변에서 [소방법 제 X조] 근거가 맞는지 다시 확인해줘"` |

- **(멘트)** "할루시네이션이 발생한다고 AI가 쓸모없는 게 아닙니다. 초안·아이디어·구조 잡기엔 탁월합니다. 단, 법령 번호·수치·고유명사는 반드시 사람이 검증해야 합니다. 이게 AI와 일하는 기본 원칙입니다."
- **(전환)** "그리고 마지막으로, 무엇을 입력해서는 안 되는지 꼭 짚고 넘어갑시다."
