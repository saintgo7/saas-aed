# M2 — 자동차·특장차 업무용 프롬프트 예시집

> **chat.pamout.com에 그대로 복사·붙여넣기 가능한 완결형 프롬프트 모음**
> `[ ]`로 표시된 부분은 실제 내용으로 바꿔서 사용하세요.
> 총 **55개** 프롬프트, 9개 카테고리.

---

## 사용 원칙

1. `[ ]` 변수를 내 상황에 맞게 바꿔 입력하세요.
2. 결과가 마음에 들지 않으면 같은 대화창에서 수정 지시를 추가하세요.
3. 개인정보·미공개 인증자료·영업비밀은 절대 입력하지 마세요.
4. 법령 조항·숫자·날짜는 반드시 원본 자료로 검증하세요.

---

## 카테고리 1 — 회의록 정리

### P01. 회의록 → 핵심 요약

```
다음 회의록을 읽고 핵심 결정사항만 뽑아서 정리해주세요.

[출력 형식]
- 결정 사항: (번호 목록, 각 항목에 담당자와 기한 포함)
- 미결 사항: (해결이 필요한 항목)
- 다음 회의 전 확인 사항:

[회의록 내용]
[여기에 회의록 전문 붙여넣기]
```

> **팁**: 회의록이 길어도 한 번에 붙여넣을 수 있습니다. 내용이 잘리면 "계속"이라고 입력하세요.

---

### P02. 회의록 → 공유 이메일 초안

```
다음 회의 결과를 참석자 전원에게 공유하는 이메일 초안을 작성해주세요.

[회의 정보]
- 일시: [날짜 및 시간]
- 주제: [회의 주제]
- 핵심 결정사항: [결정 내용 2~5가지]
- 다음 미팅 예정: [일정]

[조건]
- 제목 포함
- 본문: 인사 → 결과 요약 → 후속 조치 → 마무리
- 톤: 정중하고 간결하게
- 불필요한 인사말 최소화
```

> **팁**: 회의 결과를 미리 정리해두면 이 프롬프트로 공유 이메일을 30초 만에 생성할 수 있습니다.

---

### P03. 구두 메모 → 구조화된 회의록

```
아래 메모를 바탕으로 정식 회의록 형식으로 재작성해주세요.

[회의록 형식]
# [회의명] 회의록
- 일시:
- 장소:
- 참석자:

## 안건 1. [제목]
- 내용:
- 결정사항:
- 담당자 / 기한:

(안건마다 반복)

## 특이사항:
## 다음 회의:

[메모 원문]
[여기에 산발적 메모 붙여넣기]
```

> **팁**: 회의 중 빠르게 쳐둔 메모를 그대로 붙여넣어도 됩니다. AI가 구조를 잡아줍니다.

---

### P04. 회의 전 안건 목록 작성

```
다음 주 [회의 주제] 회의를 위한 안건 목록을 작성해주세요.

[배경]
- 회의 목적: [예: 소방차 납품 일정 점검]
- 참석 부서: [예: 생산팀, 품질팀, 영업팀]
- 주요 이슈: [예: 부품 수급 지연, 인증 서류 미비]
- 회의 시간: [예: 1시간]

[출력 형식]
번호 안건 목록 + 각 안건별 예상 소요시간 + 준비 담당자
```

> **팁**: 회의 전날 5분 투자로 체계적인 안건을 준비할 수 있습니다.

---

### P05. 회의 결과 → 1페이지 보고 요약

```
아래 회의 내용을 경영진 보고용 1페이지 요약으로 작성해주세요.

[요약 구성]
1. 회의 개요 (2~3줄)
2. 주요 결정사항 (3~5개 bullet)
3. 리스크 및 현안 (있는 경우)
4. 다음 단계 및 일정

[회의 내용]
[회의록 또는 메모 붙여넣기]

[조건] 경영진 눈높이에서 핵심만, 전문 약어는 풀어서 설명.
```

> **팁**: "경영진 보고용"이라고 명시하면 AI가 간결하고 임팩트 있는 표현을 선택합니다.

## 카테고리 2 — 이메일 초안

### P06. 납기 지연 통보 이메일

```
소방차 납품 일정이 지연되었음을 거래처에 정중하게 통보하는 이메일 초안을 써주세요.

[상황]
- 납품처: [거래처명 또는 기관명]
- 원래 납기: [날짜]
- 지연 사유: [예: 부품 수급 문제, 추가 검사 필요]
- 새로운 예상 납기: [날짜]
- 대응 방안: [예: 가능한 부품부터 선납품, 주 1회 진행 상황 보고]

[조건]
- 제목 포함
- 사과 + 원인 설명 + 새 일정 + 보상·대안 제시 구조
- 톤: 공식적이고 신뢰감 있게
```

> **팁**: `[날짜]`, `[거래처명]` 부분에 실제 정보를 넣기 전에 가상 정보로 먼저 초안을 잡아보세요.

---

### P07. 협력사 품질 이슈 시정요청 이메일

```
협력사에 품질 부적합(NCR) 시정을 요청하는 공문 형식 이메일을 작성해주세요.

[상황]
- 협력사: [협력사명]
- 부적합 품목: [예: 탱크로리용 밸브 어셈블리]
- 발견일: [날짜]
- 부적합 내용: [예: 치수 규격 초과, 표면 이물질 혼입]
- 요청 사항: [예: 시정조치계획서(CAPA) 5일 내 제출, 재발 방지 대책 포함]

[형식]
공문 형식 (수신·발신·제목·본문·첨부 항목 포함)
```

> **팁**: 공문 형식을 요청하면 AI가 제목에 "시정요청의 건" 같은 공식 표현을 자동으로 씁니다.

---

### P08. 내부 공지 이메일

```
아래 내용을 전사 직원에게 공지하는 이메일을 작성해주세요.

[공지 내용]
- 공지 주제: [예: 6월 안전교육 일정 안내]
- 대상: [예: 전 직원 / 생산직 직원]
- 일시: [날짜 및 시간]
- 장소: [장소]
- 필수 지참: [예: 교육 확인서, 안전화]
- 미참석 시 처리: [예: 별도 보충교육]

[조건]
- 제목 포함
- 간결하고 명확하게, 핵심 정보를 bullet로
- 문의처 포함 ([담당자명] [연락처])
```

> **팁**: 공지 이메일은 한 번 잘 만들어 두면 다음에는 날짜·장소만 바꿔 재사용할 수 있습니다.

---

### P09. 출장 결과 보고 이메일

```
출장 결과를 상급자에게 보고하는 이메일 초안을 작성해주세요.

[출장 정보]
- 목적: [예: 신규 협력사 품질현장 실사]
- 출장지: [지역 또는 회사명]
- 기간: [날짜]
- 동행자: [있는 경우]

[주요 내용]
- 현장 현황: [관찰한 내용]
- 긍정적 사항: [강점]
- 개선 필요 사항: [지적 사항]
- 권고 사항: [향후 조치 제안]

[형식] 제목 포함, 표 또는 항목별 정리
```

> **팁**: 출장 직후 기억이 생생할 때 메모를 붙여넣으면 더 풍부한 보고서가 만들어집니다.

---

### P10. 감사 및 협조 요청 이메일

```
[기관 또는 협력사명]의 [담당자명]에게 협조에 감사하고 추가 자료를 요청하는
정중한 이메일을 작성해주세요.

[감사 사유]: [예: 현장 실사 협조, 서류 신속 제공]
[추가 요청 사항]: [예: 품질검사 성적서 원본, 기술 규격서 최신본]
[요청 기한]: [날짜]

[조건]
- 짧고 정중하게 (A4 1/3 페이지 이내)
- 감사 → 요청 → 마무리 구조
```

> **팁**: 이메일이 너무 길어지면 "더 짧게, 핵심만 담아"라고 수정 요청하세요.

## 카테고리 3 — 보고 자료 구성

### P11. 주간 업무 보고서

```
이번 주 업무 내용을 바탕으로 팀장 보고용 주간 업무 보고서를 작성해주세요.

[이번 주 업무]
[업무 내용을 자유롭게 나열]
예:
- 소방차 5호 최종 품질검사 완료
- NCR 3건 중 2건 처리 완료
- 탱크로리 입고검사 준비 진행 중

[형식]
표: 업무 항목 / 내용 / 완료율 / 다음 주 계획
표 하단: 특이사항 / 건의사항 (각 2~3줄)
```

> **팁**: 매주 같은 프롬프트 구조를 쓰면 일관된 형식의 보고서를 5분 만에 만들 수 있습니다.

---

### P12. 월간 실적 보고서 초안

```
아래 수치를 바탕으로 [부서명] 월간 실적 보고서 초안을 작성해주세요.

[보고 기간]: [년 월]
[주요 수치]
- 생산 실적: [수량/목표 대비]
- 품질: 불량률 [수치]% (목표 [수치]%)
- 납기 준수율: [수치]%
- 주요 이슈: [내용]

[형식]
1. 요약 (경영진용, 3~5줄)
2. 실적 상세 (표)
3. 이슈 및 원인 분석
4. 다음 달 목표 및 대응 계획

표지 제목과 작성일 포함.
```

> **팁**: 실제 수치는 보안상 가상 수치로 연습한 후, 사내 시스템에서 확인한 실제 수치로 교체하세요.

---

### P13. 사업계획서 목차 및 개요

```
[사업 또는 프로젝트명] 사업계획서의 목차와 각 챕터 핵심 내용 개요를 작성해주세요.

[사업 개요]
- 목적: [예: 탱크로리 신규 생산라인 구축]
- 대상: [예: 내부 승인용 / 외부 투자 제안용]
- 규모: [예: 예산 [금액], 기간 [기간]]

[목차 요구사항]
- 챕터 수: 7~10개
- 포함 필수 항목: 배경 및 필요성, 목표, 추진 계획, 예산, 기대효과, 리스크 관리
- 각 챕터 아래 3~5개 세부 항목 포함
```

> **팁**: 목차가 완성되면 각 챕터를 하나씩 채워달라고 후속 요청할 수 있습니다.

---

### P14. 발표 자료(PPT) 슬라이드 개요

```
[발표 주제]에 대한 발표 슬라이드 구성(개요)을 작성해주세요.

[발표 정보]
- 주제: [예: 2024년 상반기 품질 현황 및 하반기 개선 계획]
- 발표 시간: [예: 15분]
- 청중: [예: 경영진 / 부서장 / 협력사]
- 강조 포인트: [예: 불량률 개선 성과, 하반기 목표]

[출력 형식]
슬라이드 번호 | 슬라이드 제목 | 핵심 내용 (bullet 3개 이내) | 시각 자료 제안

총 슬라이드 수: 12~15장
```

> **팁**: 슬라이드 개요가 완성되면 "슬라이드 3번 내용을 더 구체적으로 써줘"처럼 슬라이드 단위로 보완할 수 있습니다.

---

### P15. 경영진 보고용 1페이지 요약 (Executive Summary)

```
다음 보고서를 경영진이 3분 안에 읽을 수 있는 1페이지 Executive Summary로 요약해주세요.

[원본 보고서 내용]
[보고서 내용 붙여넣기]

[출력 구조]
■ 현황 (2~3줄)
■ 핵심 이슈 (bullet 3개 이내)
■ 조치 사항 / 요청 사항 (bullet 2~3개)
■ 예상 효과 / 기대 결과 (1~2줄)

[조건] 수치·날짜·담당자 명시, 전문용어 최소화
```

> **팁**: 긴 보고서 대신 이 요약을 먼저 올리면 경영진 검토 시간을 절반으로 줄일 수 있습니다.

## 카테고리 4 — 계획서 목차

### P16. 연간 품질 관리 계획서

```
특장차 제조사 품질팀의 연간 품질 관리 계획서 목차를 작성해주세요.

[조건]
- 대상 차종: [예: 소방차, 살수차]
- 포함 항목: 품질 목표, 검사 계획, 협력사 관리, 부적합 처리 절차, 개선 활동
- 각 목차 항목 옆에 작성 담당 부서 표기
- ISO 9001 요구사항 연계 가능한 구조로
- 챕터 10개 이내, 각 챕터에 3~5개 세부 항목
```

> **팁**: 특정 인증 규격(ISO, IATF 등)을 명시하면 해당 규격에 맞는 구조로 목차를 잡아줍니다.

---

### P17. 신규 차종 인증 추진 계획서

```
[차종명] 신규 모델의 자동차 안전기준 적합성 인증 추진 계획서 목차와 핵심 내용을 작성해주세요.

[차종 정보]
- 차종: [예: 25톤 카고크레인]
- 인증 유형: [예: 자기인증 / 형식승인]
- 목표 인증 완료일: [날짜]
- 담당 부서: [부서명]

[목차 포함 필수 항목]
1. 인증 근거 법령
2. 추진 일정(마일스톤)
3. 필요 시험 항목 및 기관
4. 제출 서류 목록
5. 예산 계획
6. 리스크 및 대응 방안
```

> **팁**: "법령 조항 번호는 (확인 필요)로 표시해줘"를 추가하면 검증 전 오류를 방지할 수 있습니다.

---

### P18. 안전 교육 계획서

```
[대상] 대상의 [기간] 안전교육 계획서 목차와 커리큘럼 개요를 작성해주세요.

[교육 정보]
- 대상: [예: 신입 생산직 사원 / 전 직원]
- 기간: [예: 1일 / 3일]
- 목적: [예: 특장차 생산 현장 안전사고 예방]
- 필수 포함: 법정 의무교육 항목, 현장 실습, 평가

[형식]
```

> **팁**: 현실 가능성보다 다양한 아이디어를 먼저 뽑은 다음, 팀에서 선별하는 방식이 효과적입니다.

## 카테고리 9 — 검수·검토 요청

### P41. 문서 완성도 검토 요청

```
다음 문서를 검토하고 개선이 필요한 부분을 지적해주세요.

[검토 기준]
1. 논리 구조: 논리 흐름이 자연스러운가?
2. 내용 완결성: 빠진 정보가 없는가?
3. 표현: 어색하거나 모호한 표현이 있는가?
4. 형식: 목적에 맞는 형식인가?

[문서 내용]
[검토받을 내용 붙여넣기]

검토 결과를 "위치(단락 번호 또는 문장) | 문제점 | 개선 제안" 형식 표로 정리해주세요.
```

> **팁**: 중요 서류를 제출하기 전 AI에게 검토를 맡기면 기본적인 완성도를 빠르게 높일 수 있습니다.

```

[검토 항목]

2. 해결책: 제안 내용이 구체적이고 실현 가능한가?
3. 기대 효과: 숫자나 구체적 근거가 있는가?
4. 리스크: 예상 반론에 대한 대비가 있는가?

[제안서 내용]
[내용 붙여넣기]

각 항목별 점수(10점 만점)와 개선 제안을 주세요.
```

> **팁**: AI 점수는 절대적 기준이 아닙니다. 개선 방향 파악에 참고용으로만 쓰세요.

### P43. 이메일 발송 전 최종 점검

```
5. 제목이 내용을 잘 반영하는지

[이메일 내용]
[이메일 붙여넣기]
```

> **팁**: 중요한 외부 이메일 발송 전 30초 투자로 실수를 방지할 수 있습니다.

```
리스크 설명 | 발생 가능성(상/중/하) | 영향도(상/중/하) | 대응 방안
```

### P45. 데이터·수치 논리 검토

```

[검토 포인트]

4. 추가 데이터가 필요한 부분은?

[보고서 내용]
[보고서 붙여넣기]

[중요] AI는 수치 검증에 한계가 있습니다. 최종 확인은 원본 데이터와 대조해주세요.
```

> **팁**: 계산 오류나 논리 비약을 AI가 잡아줄 수 있지만, 100% 신뢰는 금물입니다. 반드시 사람이 최종 확인하세요.

### P49. 규정·절차서 초안 갭 분석

```

[절차서 목적]: [예: 부적합품 처리 절차]
[적용 대상]: [예: 품질팀, 생산팀]

갭 분석 항목:
1. 담당자가 불명확한 단계
2. 예외 상황 처리 기준이 없는 부분
3. 다른 절차서와 충돌 가능성
4. 현장 실행 가능성 의문 항목

[절차서 초안]
[내용 붙여넣기]
```

> **팁**: 절차서 초안 작성 후 이 프롬프트로 공백을 찾아내면 현장 운영 전 사전 보완이 가능합니다.
