## 1. AI란 무엇인가 — 개념 계층 이해

### 1.1 러시아 인형처럼 겹겹이 쌓인 개념

AI(인공지능)에 관련된 용어들이 뉴스와 광고에 뒤섞여 등장합니다. 이 용어들은 사실 하나의 계층 구조를 이룹니다. 러시아의 전통 인형 '마트료시카'처럼, 바깥 인형 안에 더 작은 인형이 들어있는 구조입니다.

```
┌──────────────────────────────────────────────┐
│  AI (인공지능)                                │
│  ┌──────────────────────────────────────┐    │
│  │  머신러닝 (Machine Learning)          │    │
│  │  ┌──────────────────────────────┐    │    │
│  │  │  딥러닝 (Deep Learning)       │    │    │
│  │  │  ┌────────────────────────┐  │    │    │
│  │  │  │  생성형 AI              │  │    │    │
│  │  │  │  ┌──────────────────┐  │  │    │    │
│  │  │  │  │  LLM (거대언어모델)│  │  │    │    │
│  │  │  │  └──────────────────┘  │  │    │    │
│  │  │  └────────────────────────┘  │    │    │
│  │  └──────────────────────────────┘    │    │
│  └──────────────────────────────────────┘    │
└──────────────────────────────────────────────┘
```

### 1.2 각 개념 설명

#### AI (인공지능, Artificial Intelligence)
**한 줄 정의**: 인간의 지적 작업을 컴퓨터가 수행하는 기술 전반

인간이 하는 작업 — 글 읽기, 말 알아듣기, 사진 구분하기, 결정 내리기 — 을 컴퓨터가 할 수 있도록 만드는 모든 기술을 포괄합니다. 스팸 메일 필터, 음성 비서 "오케이 구글", 넷플릭스 추천 알고리즘까지 전부 AI입니다.

> **자동차 비유**: '자동차'라는 넓은 범주 안에 세단·SUV·특장차가 모두 들어가듯, AI라는 넓은 범주 안에 다양한 기술이 들어있습니다.

#### 머신러닝 (Machine Learning, ML)
**한 줄 정의**: 규칙을 직접 짜주지 않고, 데이터를 보여주면 스스로 패턴을 학습하는 방식

전통 프로그래밍은 개발자가 모든 규칙을 직접 코드로 입력합니다. 머신러닝은 다릅니다. 수많은 데이터를 보여주면 컴퓨터가 스스로 패턴을 찾아냅니다.

> **자동차 비유**: 숙련된 검사 담당자가 수천 건의 서류를 보다 보면 '이 서류는 뭔가 이상하다'는 감이 생기죠? 머신러닝이 바로 그 과정을 데이터로 학습하는 것입니다.

#### 딥러닝 (Deep Learning, DL)
**한 줄 정의**: 인간 뇌의 신경망(뉴런) 구조를 흉내 내어 여러 층으로 쌓은 머신러닝 기법

'깊다(Deep)'는 것은 신경망의 층이 많다는 뜻입니다. 층이 많을수록 더 복잡한 패턴을 학습할 수 있어요. 이미지 인식, 음성 인식, 자연어 처리가 딥러닝으로 급격히 발전했습니다.

#### 생성형 AI (Generative AI)
**한 줄 정의**: 새로운 텍스트·이미지·코드를 직접 만들어내는 AI

기존 AI의 주된 역할은 '분류'였습니다. '이 부품이 불량인가 아닌가' 판별하기. 생성형 AI는 다릅니다. '이 부품 불량 보고서를 작성해줘'처럼 **새로운 내용을 만들어냅니다**.

#### LLM (Large Language Model, 거대언어모델)
**한 줄 정의**: 텍스트를 다루는 초대형 생성형 AI

LLM은 생성형 AI 중에서 언어(텍스트)를 처리하는 초대형 모델입니다. 'Large'는 수십억~수조 개의 파라미터(수치 가중치)를 가진 거대한 규모를 뜻합니다. ChatGPT, Claude, Gemini가 모두 LLM입니다.

### 1.3 정리표

| 용어 | 한 줄 정의 | 실제 예시 |
|------|-----------|---------|
| AI (인공지능) | 컴퓨터가 지적 작업을 수행하는 기술 전반 | 스팸 필터, 넷플릭스 추천 |
| 머신러닝 (ML) | 데이터로 패턴을 스스로 학습하는 방식 | 불량률 예측, 수요 예측 |
| 딥러닝 (DL) | 신경망 여러 층을 쌓아 학습 | 이미지 인식, 음성 인식 |
| 생성형 AI | 새로운 콘텐츠를 만들어내는 AI | ChatGPT, DALL·E, Midjourney |
| LLM (거대언어모델) | 언어 중심 초대형 생성형 AI | ChatGPT-4o, Claude 3.5, Gemini |

## 2. 토큰·프롬프트·할루시네이션 — LLM의 작동 원리

### 2.1 토큰(Token) — LLM이 언어를 보는 단위

LLM은 글을 '단어' 단위로 보지 않습니다. **토큰(token)**이라는 더 작은 조각으로 잘라서 처리합니다.

- 영어: 단어 1개 ≈ 토큰 1~2개
- 한국어: 단어 1개 ≈ 토큰 2~4개 (음절·형태소 단위로 쪼개짐)

**왜 중요한가?** LLM은 "이 토큰 다음에 어떤 토큰이 올 확률이 가장 높은가"를 반복 계산하면서 문장을 생성합니다. 글을 '이해'하고 '생각'하는 것이 아니라, 통계적으로 가장 자연스러운 다음 단어를 이어가는 방식입니다.

> **핵심 포인트**: LLM은 마치 '확률로 움직이는 자동완성'입니다. 이 구조가 할루시네이션의 원인이 됩니다(아래에서 자세히).

### 2.2 프롬프트(Prompt) — AI에게 주는 지시문

**프롬프트** = AI에게 주는 지시문(명령문)

프롬프트의 품질이 결과물의 품질을 결정합니다. 검색 키워드와 달리, LLM 프롬프트는 **길고 구체적이고 맥락이 풍부할수록** 좋습니다.

#### 프롬프트 품질 비교

| 구분 | 나쁜 프롬프트 (예시) | 좋은 프롬프트 (예시) |
|------|-------------------|-------------------|
| 보고서 요청 | "보고서 써줘" | "특장차 안전기준 적합성 검사 결과를 부서장에게 보고하는 A4 1장짜리 보고서를 써줘. 구성은 현황-문제점-조치계획 순서로, 존댓말 사용." |
| 요약 요청 | "요약해줘" | "아래 시험성적서 내용을 인증 담당자가 5분 안에 읽을 수 있게 3문장으로 요약해줘. 기술 용어는 쉽게 풀어서 써줘." |
| 번역 요청 | "번역해" | "아래 영문 안전기준을 한국어로 번역해줘. 기술 용어는 국토교통부 법령 표기 기준을 따라줘." |

#### 좋은 프롬프트의 4가지 요소

1. **역할(Role)**: "당신은 자동차 인증 전문가입니다" 처럼 AI에게 역할을 줍니다.
2. **맥락(Context)**: 이 작업이 어떤 상황인지 설명합니다.
3. **지시(Instruction)**: 무엇을 해달라는지 명확하게 씁니다.
4. **형식(Format)**: 결과물의 형식(분량, 구조, 어투)을 지정합니다.

### 2.3 할루시네이션(Hallucination) — AI가 거짓말을 자신 있게 하는 이유

**할루시네이션** = AI가 사실이 아닌 내용을 그럴듯하게 지어내는 오류

#### 왜 일어나는가?

LLM은 "다음 토큰이 무엇일 확률이 가장 높은가"를 계산합니다. **모르는 것에 대해서도 '자연스러운 다음 토큰'을 계속 생성합니다.** 사람처럼 "이건 모르겠습니다"라고 멈추지 않고, 학습한 패턴에서 가장 그럴듯한 답을 만들어냅니다.

#### 할루시네이션의 특징

- **자신감이 넘칩니다**: 틀린 내용도 확신 있는 어조로 씁니다.
- **그럴듯합니다**: 형식·스타일·어투가 완벽해 보입니다.
- **출처까지 지어냅니다**: 존재하지 않는 논문·법령 번호·기관명을 만들어냅니다.

#### 자동차 현장 비유

> 작업표준서가 없는 신공정에서, 경험 없는 작업자가 "이렇게 하면 될 것 같다"고 눈대중으로 작업하는 상황과 비슷합니다. 결과물이 얼핏 보면 맞아 보이지만 규격에서 벗어날 수 있어요.

#### 할루시네이션 예방 원칙 (3가지)

| # | 원칙 | 실무 행동 |
|---|------|---------|
| 1 | 사실 확인 | 규격·법령·수치는 AI 결과와 원문을 반드시 대조 확인 |
| 2 | 출처 검증 | "출처 알려줘"라고 요청 후 해당 출처가 실제 존재하는지 확인 |
| 3 | 모른다고 명시 | 프롬프트에 "모르면 모른다고 해줘"를 명시 |

> **인증 담당자 주의**: AI가 생성한 안전기준 번호, 적합성 판정 근거, 기준치 수치는 **반드시 원전(법령·고시·규격)과 대조 확인**하세요.

## 3. 자동차 산업 패러다임 전환과 AI

### 3.1 지금 자동차 산업에 무슨 일이 일어나고 있나

자동차 산업은 지금 두 가지 거대한 변화의 한가운데 있습니다.

#### 탈탄소화(De-carbonization)
- 내연기관 → 전기·수소·하이브리드 전환
- 특장차 분야에서도 전기 소방차, 전기 냉동탑차, 수소 청소차 등장
- 새로운 파워트레인 = 새로운 안전기준 = 새로운 인증 서류 체계

#### 디지털화(Digitalization)
- 종이 서류 → 전자 문서·데이터 시스템 전환
- 공정·품질 데이터의 실시간 수집·분석
- 데이터가 많아질수록 AI 활용 가능성이 커짐

### 3.2 업무별 AI 도입 가능성 (자동차·특장차 현장 기준)

| 업무 영역 | AI 도입 전 | AI 도입 후 | 기대 효과 |
|----------|-----------|-----------|---------|
| 인증 서류 초안 | 담당자 수작업 전체 | AI 초안 → 담당자 최종 수정 | 초안 작성 시간 60~70% 절감 |
| 기술기준 검색·비교 | 법령집 직접 검색, 수작업 비교 | AI 관련 조항 추출·요약 | 탐색 시간 절감 |
| 시험 보고서 서술 | 측정값 수기 입력 후 서술 | 측정값 입력 → AI 서술 초안 | 서술 작업 시간 단축 |
| 부적합(NCR) 처리 | 과거 사례 수작업 검색 | AI 유사 사례 제안·초안 작성 | 재발 방지 조치 품질 향상 |
| 회의록·보고서 | 회의 후 30분~1시간 작성 | 키워드 입력 → AI 초안 (5분) | 행정 업무 시간 단축 |
| 사내 교육자료 | 강사 전체 수작업 제작 | AI 구조·초안 제안 + 강사 보완 | 교육 자료 준비 시간 단축 |

> **중요**: 위 표의 모든 항목에서 AI는 '초안·제안·보조' 역할을 합니다. **최종 확인·판단·서명은 담당자의 몫**입니다.

### 3.3 AI 도입의 현실적인 그림

```
[기존]   담당자 → 전체 작업 → 결과물
[AI 도입] AI (초안·반복 작업) + 담당자 (판단·확인·수정) → 결과물
```

AI는 담당자를 대체하는 것이 아니라, **반복적·시간 소모적 작업을 먼저 처리하여 담당자가 더 중요한 판단 업무에 집중하도록 돕는 도구**입니다.

## 4. AI가 잘하는 것 vs 못하는 것

### 4.1 AI가 잘하는 것 (적극 활용 추천)

| 잘하는 것 | 설명 | 업무 적용 예시 |
|---------|------|-------------|
| **텍스트 초안 생성** | 맥락과 형식을 주면 빠르게 초안을 만든다 | 보고서·공문·안내문·교육자료 초안 |
| **긴 문서 요약** | 수십 페이지에서 핵심만 뽑아준다 | 시험성적서·기술기준 요약 |
| **유사 사례 제안** | 학습한 패턴에서 비슷한 사례를 제시한다 | NCR 조치 방향 참고 |
| **번역·언어 변환** | 영문 기준→한국어, 기술 용어→평이한 말 | 영문 안전기준 번역·해석 |
| **형식 변환** | 문장↔표, 긴 글↔요약 | 보고 내용을 표로, 표를 설명문으로 |

### 4.2 AI가 못하거나 위험한 것 (검증 필수)

| 주의 영역 | 이유 | 실무 대응 |
|---------|------|---------|
| **최신 법령·규격 수치** | 학습 데이터에 시간 제한이 있어 최신 개정 내용 모를 수 있음 | 원전(법령·고시) 직접 대조 |
| **미공개 내부 데이터** | AI는 그 데이터를 학습하지 않아 엉뚱한 답 줄 수 있음 + 유출 위험 | 내부 민감 데이터 입력 금지 |
| **복잡한 수치 계산** | LLM은 텍스트 모델, 수치 계산 오류 가능 | 계산은 직접 또는 검증된 도구 사용 |
| **인증 적합성 최종 판단** | 최종 판단은 담당자의 법적 책임 | AI는 참고용, 담당자가 최종 결정 |
| **경영·전략 의사결정** | 현장 맥락·조직 상황을 AI가 모름 | 의사결정의 참고자료로만 사용 |

### 4.3 한 줄 원칙

> **"AI는 초안을 써준다. 판단은 내가 한다."**

## 5. 보안·저작권·윤리 유의사항

### 5.1 보안 (Security)

AI 서비스에 입력한 내용은 서비스 제공 서버로 전송됩니다. 아래 내용은 **절대 입력하지 마십시오**.

```
❌ 절대 입력 금지
  • 개인정보 (이름, 주민등록번호, 연락처, 직원 정보)
  • 미공개 인증 자료 (시험 전 성적서, 비공개 설계 데이터)
  • 영업비밀 (원가 정보, 계약 조건, 신규 모델 개발 계획)

✅ 입력 가능
  • 공개된 법령·기준 내용
  • 개인정보가 제거된 일반 업무 상황 설명
  • 가상의 사례·예시
  • 일반적인 문서 형식·양식
```

**실무 팁**: 개인정보가 포함된 상황을 AI에 물어볼 때는 개인정보 부분을 "OOO", "A직원", "B업체"처럼 익명으로 바꾸면 대부분 해결됩니다.

> **자동차 비유**: 공장 외부인 출입 통제처럼, 어떤 정보를 AI에게 넣을지 경계를 미리 정해두세요.

### 5.2 저작권 (Copyright)

| 사항 | 내용 |
|------|------|
| AI 생성 결과물의 저작권 | 현행 한국 저작권법상 AI 단독 생성물은 저작권 보호 받지 않음. 사람이 창작적 기여를 더한 경우 달라질 수 있음 |
| 실무 원칙 | AI 결과물을 '초안'으로 받아 실질적으로 수정·검토 후 사용 → 리스크 최소화 |
| 주의사항 | AI가 생성한 이미지·텍스트가 특정 저작물을 무단 복제했을 가능성 있음. 공식 자료에 그대로 붙여넣기 전 확인 필요 |

### 5.3 윤리 (Ethics)

| 원칙 | 실무 행동 |
|------|---------|
| **투명성** | 공식 보고서에 AI 보조 사실을 내부적으로 공유 |
| **편향 경계** | AI 결과물에 편향된 판단이 섞여 있을 수 있음 — 비판적으로 검토 |
| **책임 소재** | AI가 쓴 내용도 최종 서명자가 책임 — "AI가 써서" 면책 불가 |

### 5.4 3줄 요약 카드

```
보안: 개인정보·미공개 자료·영업비밀 → 입력 금지
저작권: AI 결과물은 초안, 실질 수정 후 사용
윤리: AI 사용 투명하게, 편향 비판적 검토, 책임은 담당자에게
```

## 7. 용어 미니사전

| 용어 | 뜻 |
|------|-----|
| **AI (인공지능)** | Artificial Intelligence. 인간의 지적 작업을 컴퓨터가 수행하는 기술 전반 |
| **머신러닝 (ML)** | Machine Learning. 데이터 패턴을 스스로 학습하는 알고리즘 |

| **신경망 (Neural Network)** | 인간 뇌의 뉴런 연결을 모방한 수학적 모델 |
| **생성형 AI (Generative AI)** | 새로운 텍스트·이미지·코드를 생성하는 AI |
| **LLM (거대언어모델)** | Large Language Model. 텍스트를 처리하는 초대형 생성형 AI |
| **토큰 (Token)** | LLM이 언어를 처리하는 최소 단위. 단어보다 작을 수 있음 |
| **프롬프트 (Prompt)** | AI에게 주는 지시문·명령문 |
| **할루시네이션 (Hallucination)** | AI가 사실이 아닌 내용을 자신 있게 지어내는 오류 |
| **파라미터 (Parameter)** | AI 모델이 학습을 통해 얻은 수치 가중치. 모델의 '지식'을 표현 |
| **생성형 AI 모델 (Foundation Model)** | 방대한 데이터로 사전학습된 대형 AI 모델 |
| **탈탄소화** | 이산화탄소 배출을 줄이는 방향으로 전환하는 것. 전기차·수소차 전환이 대표적 |
| **디지털화** | 업무 프로세스를 데이터·시스템 기반으로 전환하는 것 |
| **NCR (부적합보고서)** | Non-Conformance Report. 품질 기준에 미달하는 항목의 보고서 |
| **CAPA** | Corrective and Preventive Action. 시정 및 예방 조치 |
| **형식승인** | 자동차 제작 전 안전기준 적합성을 확인하는 인증 절차 |
| **자기인증** | 제조사가 자체적으로 안전기준 적합성을 확인·선언하는 방식 |

**Q1. AI·머신러닝·딥러닝·LLM의 관계를 옳게 설명한 것은?**

① AI와 머신러닝은 전혀 다른 별개의 기술이다
② 머신러닝은 AI의 한 방법이고, 딥러닝은 머신러닝의 한 기법이다
③ LLM이 가장 넓은 개념이고 AI가 그 안에 들어간다
④ 딥러닝과 생성형 AI는 같은 것이다

> **정답: ②**
> **해설**: AI(가장 넓음) → 머신러닝 → 딥러닝 → 생성형 AI → LLM(가장 구체적) 순의 계층 구조입니다. LLM은 가장 좁고 구체적인 개념입니다.

---

**Q2. LLM이 글을 생성하는 방식을 가장 잘 설명한 것은?**

① 사람처럼 내용을 이해하고 논리적으로 서술한다
② 인터넷을 실시간으로 검색해 정보를 가져온다
③ 이전 토큰들을 바탕으로 다음 토큰이 올 확률을 계산해 이어간다
④ 미리 저장된 답변 데이터베이스에서 가장 비슷한 것을 찾아 복사한다

> **정답: ③**
> **해설**: LLM은 '다음에 올 확률이 가장 높은 토큰'을 반복 생성하는 방식입니다. 사람처럼 이해하거나 실시간 검색하는 것이 아닙니다.

---

**Q3. 할루시네이션(Hallucination)의 올바른 설명은?**

① AI가 고의로 거짓 정보를 생성하는 악의적 행위
② AI가 모르는 내용에 대해 그럴듯한 내용을 지어내는 오류
③ AI 서버 오류로 인해 응답이 중단되는 현상
④ AI가 너무 긴 문장을 생성할 때 발생하는 속도 저하

> **정답: ②**
> **해설**: 할루시네이션은 고의가 아닙니다. LLM의 구조상 모르는 내용에 대해서도 '자연스러운 다음 토큰'을 생성하는 과정에서 사실과 다른 내용을 만들어냅니다.

---

**Q4. 다음 중 AI(LLM)에게 절대 입력하면 안 되는 것은?**

① 공개된 안전기준 조항 내용
② 아직 승인되지 않은 시험성적서 원본
③ 회의록 작성에 쓸 가상의 상황 예시
④ 일반적인 보고서 양식 설명

> **정답: ②**
> **해설**: 미공개 인증자료·영업비밀·개인정보는 AI에 입력하면 안 됩니다. 공개 정보, 가상 사례, 일반 양식 설명은 사용 가능합니다.

---

**Q5. 프롬프트를 잘 쓰는 원칙으로 옳지 않은 것은?**

① 역할(Role)을 AI에게 부여하면 결과 품질이 높아진다
② 짧고 핵심 단어만 쓸수록 AI가 더 정확하게 이해한다
③ 결과물의 형식(분량, 구조, 어투)을 구체적으로 지정하는 것이 좋다
④ 맥락(배경 상황)을 충분히 설명할수록 결과가 좋아진다

> **정답: ②**
> **해설**: LLM 프롬프트는 검색 키워드와 다릅니다. 길고 구체적으로, 역할·맥락·지시·형식을 담을수록 품질이 올라갑니다.

---

**Q6. 자동차 산업에서 AI 활용이 커지는 배경으로 올바르지 않은 것은?**

① 전기차·수소차 전환으로 새로운 인증 서류 체계가 필요해졌다
② 자율주행 기술이 발전해 일반 도로에서 무인 주행이 가능해졌다
③ 디지털화로 품질·공정 데이터가 많아져 AI 분석 가능성이 커졌다
④ 탈탄소화로 복잡해진 기술기준 문서 검토에 AI 보조가 유용해졌다

> **정답: ②**
> **해설**: 이 과정은 자율주행을 다루지 않습니다. 나머지 항목(전기차 전환, 디지털화, 탈탄소화)은 모두 AI 활용 필요성이 커지는 실제 배경입니다.

**Q7. AI가 잘하는 업무로만 묶인 것은?**

① 최신 법령 수치 확인, 인증 적합성 최종 판단
② 보고서 초안 작성, 긴 문서 요약, 번역
③ 복잡한 구조계산, 미공개 설계데이터 분석
④ 경영 전략 수립, 리콜 여부 법적 판단

> **정답: ②**
> **해설**: 보고서 초안 작성, 문서 요약, 번역은 LLM이 잘하는 대표적인 업무입니다. 나머지 항목들은 AI 결과를 그대로 믿으면 위험합니다.

**Q8. AI가 생성한 결과물의 저작권에 관한 설명으로 가장 적절한 것은?**

① AI 생성 결과물은 항상 완전한 저작권 보호를 받는다
② 한국 저작권법상 현재 AI 단독 생성물은 저작권 보호를 받지 않는 것이 원칙이다
③ AI가 생성했으므로 서비스 제공사가 모든 저작권을 가진다
④ AI 생성 결과물은 공개 도메인(public domain)이므로 어디든 자유롭게 사용 가능하다

> **정답: ②**
> **해설**: 현행 한국 저작권법상 AI 단독 생성물은 저작권 보호 대상이 아닌 것이 원칙입니다. 다만 법제도가 계속 변하고 있으므로, AI 결과물을 초안으로 받아 실질적으로 수정·보완 후 사용하는 것이 리스크를 줄이는 방법입니다.
