## M5 — 현업 적용 과제 도출(1) (11:00~12:00)

### ■ 오프닝 & 조 편성 (11:00~11:10, 10분)

**강사 멘트 (구어체)**

> "오늘 오전에는 AI가 어떤 일을 할 수 있는지 함께 보셨고, 방금 M4에서는 품질·안전·인증 현장 사례까지 확인하셨습니다. 이제는 '그래서 내 부서에서는 어떻게 쓸까?'를 직접 설계하는 시간입니다. 이론을 실무로 연결하는 가장 중요한 시간이에요."

**조 편성 방법 (강사 안내)**

- 사전에 참석자 명단을 부서별로 분류해 **4~6명씩** 조 구성
- 가능하면 **다부서 혼합**을 권장 (기획+품질+인증+생산 혼합 시 시야 넓어짐)
- 단일 부서 인원이 많으면 동 부서 내 2개 조로 분리 가능

| 역할 | 인원 | 책임 |
|---|---|---|
| **조장(퍼실리테이터)** | 1명 | 논의 흐름 관리, 시간 체크, 결론 수렴 |
| **기록자(서기)** | 1~2명 | 워크시트 작성, chat.pamout.com 입력 |
| **발표자** | 1명 | M7에서 3분 발표 담당 |
| **자유 멤버** | 나머지 | 아이디어 제공, 매트릭스 채점 |

> **강사 팁**: 역할은 자발적으로 정하게 하되, 30초 내 결정 안 나면 강사가 "번호 순서대로" 지정. 강사 멘트: _"조장은 오늘 가장 많이 말씀하셔야 합니다. 기록자는 가장 빠르게 타이핑하시는 분이 맡아주세요."_

**오리엔테이션 (5분)**

강사가 화면/화이트보드에 다음 3가지를 공유:

1. 오늘 워크숍 3단계 결과물: 페인포인트 목록 → 과제 매트릭스 → 실행계획서
2. 평가 기준: **실현 가능성**을 최우선으로 (거창한 아이디어보다 내일 당장 쓸 수 있는 것)
3. 도구: chat.pamout.com을 브레인스토밍 보조 도구로 적극 활용할 것

### ■ Step1 — 페인포인트 브레인스토밍 (11:10~11:35, 25분)

**강사 멘트**

> "페인포인트(Pain-point)는 '아, 이거 매번 하기 힘든데'라는 감각입니다. 거창한 문제보다, 매일 반복되는 귀찮은 일, 빠뜨리기 쉬운 일, 다른 부서에 물어봐야 하는 일을 먼저 꺼내주세요."

**진행 순서**

1. **개인 작업 (5분)**: 각자 포스트잇(노란색)에 내 업무 중 불편한 점 3개 이상 작성. 조 공유 전 개인 생각 먼저 고정.

2. **조 공유 (10분)**: 한 명씩 돌아가며 포스트잇을 화이트보드/전지에 붙이면서 30초 설명. 비슷한 내용은 묶기.

3. **chat.pamout.com 활용 (5분)**: 기록자가 아래 프롬프트를 입력해 AI 추가 제안을 받음.

```
우리 조는 [부서명]에서 일하는 자동차/특장차 관련 직원들입니다.
현재 업무에서 발굴한 주요 페인포인트는 다음과 같습니다:
[조에서 나온 페인포인트 목록 붙여넣기]

위 내용을 참고하여, 우리가 빠뜨렸을 수 있는 추가 페인포인트를 5가지 더 제안해주세요.
각 항목은 "업무 유형 — 구체적 불편 내용 — 발생 빈도(일/주/월)" 형식으로 작성해주세요.
```

4. **통합 (5분)**: AI 제안 중 공감 가는 항목을 분홍색 포스트잇으로 추가. 최종 목록 정리.

**막힐 때 강사가 던질 질문**

- "매월 반복해서 만드는 문서가 있나요? 그 문서 만들 때 가장 힘든 단계는 어디인가요?"
- "다른 부서나 담당자에게 확인 전화를 자주 하는 업무가 있나요? 왜 그 정보를 바로 못 찾으시나요?"
- "연간 감사나 인증 심사 직전에 특히 바빠지는 이유가 뭔가요?"
- "신입이 들어왔을 때 가장 먼저 알려줘야 하는 반복 업무는 무엇인가요?"
- "엑셀 파일 중에서 여러 사람이 동시에 고쳐서 버전이 꼬이는 파일이 있나요?"

**조별 순회 코칭 팁 (강사용)**

- 조가 침묵하면 → "현재 진행 중인 인증 과제나 검사 항목 중에서 가장 서류가 많은 게 뭔가요?" 구체적 상황 질문으로 물꼬 트기
- 추상적 페인포인트만 나오면 ("효율이 낮다") → "그 비효율이 구체적으로 어느 단계에서, 얼마나 자주 발생하나요?" 구체화 유도
- 너무 많이 나오면 → "오늘 실행계획을 완성해야 하니 최대 8~10개로 압축해봅시다"
- IT/기술 과제만 나오면 → "예산·코딩 없이, 지금 쓰는 노트북과 인터넷만으로 해결 가능한 것도 찾아보세요"

### ■ Step2 — 과제 선정 & 임팩트×실현가능성 매트릭스 (11:35~12:00, 25분)

**강사 멘트**

> "모든 페인포인트를 다 해결할 수는 없습니다. 오늘 우리가 고를 기준은 딱 두 가지입니다. 첫째, 해결하면 얼마나 도움이 되는가(임팩트). 둘째, 지금 우리가 실제로 할 수 있는가(실현가능성). 이 두 축으로 점수를 매겨봅시다."

**매트릭스 작성 방법 (워크시트 참조)**

1. 페인포인트 목록 각 항목에 대해 조원 전체가 **임팩트(1~5점)** 와 **실현가능성(1~5점)** 을 각자 평가
2. 조원 평균 점수 계산 → 매트릭스 4사분면에 배치

```
실현가능성 높음
        │
  [빠른성과] │ [전략과제]
  (우선착수) │ (중기목표)
────────────┼────────────  임팩트
  [보류]   │ [장기검토]
            │
        실현가능성 낮음
```

3. **우선순위 과제 2~3개 선정**: 임팩트×실현가능성 합산 점수 상위 + 조원 합의

**강사 멘트 (매트릭스 설명 후)**

> "오른쪽 위 '전략과제'는 중요하지만 시간이 걸립니다. 오늘은 왼쪽 위 '빠른성과(Quick Win)'에서 1~2개를 골라 실행계획을 만드는 것을 권장합니다. 작지만 실제로 써보는 것이 AI 도입의 첫걸음입니다."

**막힐 때 강사가 던질 질문**

- "이 과제를 해결하면 1주일에 몇 시간이 줄어드나요?"
- "지금 당장 chat.pamout.com에서 프롬프트 하나 만들면 30% 해결되는 것이 있나요?"
- "팀장 결재 없이 혼자서 시작해볼 수 있는 것이 있나요?"

**조별 순회 코칭 팁 (강사용)**

- 과제가 너무 크게 잡혀 있으면 → "이 과제에서 딱 첫 번째 단계만 뽑는다면?" 분해 유도
- 과제가 너무 소소하면 → "이게 자동화되면 한 달에 몇 시간이 절약되나요? 숫자를 한 번 추정해보세요"
- 결정을 못 내리면 → "실현가능성이 높은 것 한 개만 골라봅시다. 점심 후에 더 다듬을 수 있습니다"

### ■ Step3 — 우선순위 과제 실행방안 구체화 (13:10~13:50, 40분)

**강사 멘트**

> "과제가 선정됐다면 이제 '어떻게'를 채워야 합니다. AI 도구를 어떻게 쓸지, 어떤 프롬프트가 필요한지, 누가 담당할지를 정합니다. chat.pamout.com에서 직접 프롬프트를 짜보는 것도 이 시간에 합니다."

**구체화 항목 (워크시트 실행계획서 섹션 참조)**

| 항목 | 작성 가이드 |
|---|---|
| **과제명** | 동사+목적어 형식 ("인증서류 누락 자동 점검", "주간보고 초안 자동 생성") |
| **현황 기술** | 현재 어떻게 하고 있는지 3줄 이내 |
| **AI 활용 방안** | chat.pamout.com / Codex / Claude 중 어떤 도구로, 어떤 단계에 적용 |
| **핵심 프롬프트** | 실제 사용할 프롬프트 초안 (chat.pamout.com에서 테스트) |
| **기대 효과** | 시간 절감(시간/주), 오류 감소(%), 기타 정성 효과 |
| **담당자** | 누가 첫 번째로 시작할 것인지 |
| **1차 실행 일정** | 교육 후 2주 내 가능한 첫 번째 액션 |

**chat.pamout.com 실시간 프롬프트 작성 가이드 (Step3 전용)**

기록자가 아래 프롬프트로 AI와 함께 실행방안 도출:

```
나는 [회사명/부서명]에서 일하는 [직책]입니다.
다음 업무 과제에 AI를 활용하려고 합니다:

과제명: [과제명]
현재 방식: [현재 어떻게 하고 있는지 2~3줄]
원하는 결과: [AI를 쓰면 어떻게 달라졌으면 하는지]

질문 1: 이 과제에 chat.pamout.com (ChatGPT 계열 LLM)을 활용하는 가장 효과적인 방법 3가지를 알려주세요.
질문 2: 각 방법에서 실제로 사용할 프롬프트 예시를 작성해주세요.
질문 3: 이 방법을 처음 시작할 때 가장 먼저 해야 할 한 가지 액션은 무엇인가요?
```

**조별 순회 코칭 팁 (강사용)**

- "핵심 프롬프트"를 아직 못 쓴 조 → 강사가 직접 chat.pamout.com 열어서 함께 입력. "제가 옆에서 같이 써볼게요."
- AI 활용 방안이 막연한 경우 → "이 업무에서 반복되는 패턴이 있나요? 그 패턴을 프롬프트로 만드는 게 출발입니다."
- 너무 완벽하게 만들려는 조 → "오늘은 60점짜리 계획서도 충분합니다. 시작이 중요합니다."
- 도구 선택을 못 하는 조 → "일단 chat.pamout.com으로 시작하세요. 익숙해지면 Claude나 Codex로 확장하면 됩니다."

### ■ Step4 — 예상 장애요인 & 극복방안 (13:50~14:15, 25분)

**강사 멘트**

> "가장 좋은 계획도 현실에서 막히면 소용없습니다. '왜 못 할 수도 있는가'를 미리 생각하는 것이 성공 확률을 높입니다. 솔직하게 장애요인을 꺼내봅시다."

**장애요인 유형별 극복 프레임**

| 장애요인 유형 | 흔한 예시 | 극복 방향 |
|---|---|---|
| **보안/정보유출 우려** | "회사 내부 자료를 AI에 넣어도 되나요?" | 개인정보·영업비밀 제외 원칙 확인 후 일반적 업무 서술로 변환해 입력 |
| **상사·조직의 저항** | "팀장님이 AI 쓰는 걸 싫어하세요" | 결과물을 직접 보여주기, 작은 성과부터 시연 |
| **디지털 역량 부족** | "저는 잘 못 쓸 것 같아요" | chat.pamout.com은 한글 입력만으로 충분. 동료와 페어 작업 |

### ■ Step5 — 1페이지 실행계획서 완성 (14:15~14:50, 35분)

**강사 멘트**

> "지금까지 논의한 내용을 1페이지 실행계획서에 옮기는 시간입니다. 이 문서가 오늘 워크숍의 최종 산출물이고, M7 발표에서 보여줄 내용입니다. 완벽하지 않아도 됩니다. 오늘 배운 것을 토대로 다음 달까지 실제로 실행할 수 있는 계획이면 충분합니다."

**실행계획서 완성 체크리스트**

- [ ] 과제명이 동사+목적어 형식으로 명확한가?
- [ ] 현황 기술에 구체적 수치(주 X시간, 월 X건)가 포함됐는가?
- [ ] AI 활용 방안에 사용 도구(chat.pamout.com 등)가 명시됐는가?
- [ ] 실제 사용할 프롬프트 초안이 있는가?
- [ ] 기대효과에 정량 지표(시간 절감 X시간/주 등)가 있는가?
- [ ] 1차 실행 일정이 교육 후 2주 내로 설정됐는가?
- [ ] 담당자가 실명으로 기재됐는가?
- [ ] 예상 장애요인과 극복방안이 최소 1건 기재됐는가?
- [ ] 성공지표(KPI)가 측정 가능한 형태인가?

**chat.pamout.com 실행계획서 작성 보조 프롬프트**

```
다음은 내가 작성 중인 AI 활용 실행계획서 초안입니다.
내용을 검토하고 개선 제안을 해주세요.

[과제명]: [입력]
[현황]: [입력]
[AI 활용 방안]: [입력]
[기대효과]: [입력]
[1차 일정]: [입력]
[장애요인]: [입력]

검토 요청 사항:
1. 과제 범위가 너무 크거나 모호하지 않은지 확인해주세요.
2. 기대효과를 더 구체적 수치로 표현할 방법을 제안해주세요.
3. 장애요인에 빠진 것이 있다면 추가 제안해주세요.
4. 성공 여부를 판단할 수 있는 성공지표(KPI) 2~3개를 제안해주세요.
```

**조별 순회 코칭 팁 (강사용)**

- 실행계획서 작성이 늦은 조 → "일정과 담당자 두 칸만 먼저 채우세요. 나머지는 채워지면서 갑니다."
- 과제가 2~3개인 경우 → "가장 자신 있는 1개만 완성하고, 나머지는 메모 수준으로 남겨두세요."
- 기대효과를 너무 부풀리는 경우 → "현실적인 숫자가 더 신뢰감 있습니다. 현재 소요 시간의 20~30% 절감부터 시작해보세요."
- 발표를 걱정하는 조 → "M7 발표는 이 계획서를 그대로 읽으셔도 됩니다. 화려한 발표 아닙니다."
