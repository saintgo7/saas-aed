# 강의 슬라이드 덱 JSON 스키마 + 작성 규칙

`tools/deckbuilder/build_pptx.py` 가 읽는 입력 형식. **유효한 JSON 한 개**를 만든다.

## 최상위 구조
```json
{
  "course": "자동차 산업 임직원을 위한 실무형 AI 활용 특강",
  "title": "(이 덱 제목, 예: AI 및 생성형 AI 개요)",
  "subject": "AI 활용 실무 특강",
  "author": "특장차인증센터 교육운영팀",
  "slides": [ {레이아웃 객체}, ... ]
}
```
- `course` 는 모든 슬라이드 하단 푸터에 표시된다. 위 문자열 그대로 사용.
- `author` 는 위 문자열 그대로. (절대 AI/모델/도구 이름을 넣지 말 것.)

## 슬라이드 레이아웃 종류 (`layout` 필드)

각 content 슬라이드에는 가능한 한 `notes`(발표자 노트)를 단다 — 강사가 실제로 말하듯 구어체 2~5문장.

1. **title** — 표지(덱 맨 앞 1장)
   ```json
   {"layout":"title","kicker":"Day 1 · Module 1","title":"...","subtitle":"한 줄 부제",
    "org":"한국교통안전공단 자동차안전연구원 특장차인증센터","date":"2026","presenter":"진행: 본 강사"}
   ```
2. **section** — 섹션 전환(파트 시작마다). 번호는 자동.
   ```json
   {"layout":"section","title":"파트 제목","subtitle":"이 파트에서 다룰 한 줄"}
   ```
3. **bullets** — 기본 본문. `lead`(선택, 강조 한 줄), `bullets` 배열.
   ```json
   {"layout":"bullets","kicker":"선택: 좌측 상단 작은 라벨","title":"슬라이드 제목","lead":"선택 강조문",
    "bullets":[{"text":"1차 항목","level":0},{"text":"하위 설명","level":1},{"text":"더 하위","level":2}],
    "font":17, "notes":"강사 멘트..."}
   ```
   - `level` 0/1/2 만 사용. 한 슬라이드 bullet은 3~6개 권장(너무 균일하게 채우지 말 것).
3. **two_col** — 좌우 비교/대조.
   ```json
   {"layout":"two_col","title":"...","left":{"title":"왼쪽 머리","bullets":["...","..."]},
    "right":{"title":"오른쪽 머리","bullets":["...","..."]},"notes":"..."}
   ```
4. **table** — 표. 첫 행은 머리행. 2~4열, 3~7행 권장.
   ```json
   {"layout":"table","title":"...","table":[["열1","열2"],["a","b"]],"notes":"..."}
   ```
5. **takeaway** — 핵심 한 줄 강조(짙은 배경, 큰 글씨). 파트/덱의 결론에.
   ```json
   {"layout":"takeaway","label":"핵심 정리","text":"한두 문장으로 강하게.","notes":"..."}
   ```
6. **quote** — 인용/문제제기 한 문장.
   ```json
   {"layout":"quote","text":"...","by":"선택 출처","notes":"..."}
   ```
7. **closing** — 마무리(덱 맨 끝).
   ```json
   {"layout":"closing","title":"다음 시간 / 정리","lines":["줄1","줄2"]}
   ```

## "사람이 만든 듯한" 스타일 규칙 (매우 중요)
- **이모지 금지.** 불릿 기호·장식 남발 금지.
- 기계적 대칭 금지: 모든 슬라이드가 똑같이 5불릿 X. 어떤 슬라이드는 1문장, 어떤 건 표, 어떤 건 비교.
- 문장은 **실제 강사 말투**로. "~합니다/~해 봅시다/~죠" 섞어 자연스럽게. 번역투·과한 개조식 나열 회피.
- 자동차·특장차 현장의 **구체적 예시·숫자·상황**을 넣는다(소방차 입고검사, 자기인증 서류 누락 등).
- AI가 흔히 쓰는 상투구("이번 시간에는 ~에 대해 알아보겠습니다"의 반복, "결론적으로", "~을 통해 ~할 수 있습니다") 남발 금지.
- 슬라이드 제목은 메시지형으로(예: "AI는 사실을 '확인'해야 한다" > "AI의 한계").
- `notes`는 슬라이드에 안 적은 부연·전환·발문을 담는다(슬라이드 텍스트 복붙 금지).
- 분량: 한 덱 **24~38장**. 표지·섹션·takeaway·closing 포함.

## 산출
- 파일 1개를 `build/decks/<파일명>.json` 으로 Write.
- 반드시 `json.loads` 로 파싱되는 유효 JSON(트레일링 콤마 금지, 큰따옴표 이스케이프 주의).
